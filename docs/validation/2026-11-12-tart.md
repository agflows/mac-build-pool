# Tart validation on the MacBook Pro M1

The protected controller and loopback validation broker were staged on November
12, 2026. Public activation is gated on completed acceptance. The validation
broker reported the `macOS-vm` boundary, `executorInstalled: true`, and disabled
signing and USB APIs.

The powered-off base uses Tart 2.41.1, macOS 26.6.2 (25G83), Xcode 26.6 (17F113),
and an Apple-verified arm64 iOS 26.5 runtime (23F77). The runtime remained
available after a clean guest shutdown and restart. The base disk SHA-256 is
`f05990dbd7c482a6236d60443ecc50414ccbd5ca8f0c6f178de6abe86a25b0fc`.
Node 24.22.3, Bun 1.4.4, CocoaPods 1.17.0, Ruby 4.0.9, and Flutter 3.50.0 were
provisioned. The base contains a fresh worker simulator and no project builds.

The macOS regression suite passed 165 tests. A fresh six-GiB local VM lease
passed the guest preflight, including host-file and LAN/tailnet/direct-network
denials, an empty guest SSH agent, non-admin execution, protected toolchains,
and an approved package fetch. The Expo/Bun preparation and CocoaPods install
succeeded for CoupleApp commit `b83e613a54d79323e798a99589b76c8e696770aa` in
preparation job `4ebdb4f788db3a74`. Its acceptance snapshot adds only a dependency
hook invoking the protected probe. The app repository remains clean. Public
app configuration was supplied separately from the source archive.

CocoaPods redirected a spec download to jsDelivr. The relay allowed only
CocoaPods spec reads on that host. In the running guest, the required
SocketRocket spec returned HTTP 200 and an unrelated npm path returned HTTP 403.
The worker issued a relay leaf for the configured destinations from the guest's
existing CA before running project code.

A fresh 4 GiB lease repeated the guest checks and finished the same real
CoupleApp preparation in job `8d1e4fc63e25bd8f`. The relay returned HTTP 200
for the approved React Native iOS artifact and HTTP 403 for an unrelated path
on the same mirror. CocoaPods selected the prebuilt React Native Core and
dependencies instead of compiling them from source. The mirror rule is
limited to versioned React Native and Hermes iOS binaries and their checksums.
The subsequent Release job `fe7fe179d7f53d98` was interrupted by urgent host
memory pressure with approximately 21 GiB of disk free. The guard stopped the
guest and its disposable clone was removed. No simulator artifact was produced.
The pinned image declares a 4 GiB minimum. Tart rejected a 3 GiB profile during
setup, before boot, and the controller removed the unused clone.

A second 4 GiB Release run began at normal host pressure with stable swap. It
passed the guest probes and package preparation again. Compile job
`af65944272854b4a` produced more than 780 objects before it reached the original
30-minute job deadline. The controller reported the timeout and removed the
disposable guest. The build deadline now allows up to 45 minutes. Memory and
disk guards still apply throughout the job.

The extended build job `920e98fce3084668` repeated approved package preparation
and compiled at least 438 objects before the Mac reached urgent memory
pressure. The guard stopped the guest with approximately 18 GiB of disk
space still available. This run did not produce a CoupleApp simulator artifact.

SwiftProbe resolved its pinned swift-collections 1.3.0 package in a local
4 GiB lease. The first build timed out while using a different package cache.
Reusing the prepared checkout for scheme discovery, build and tests let the
retry compile and launch. Build job `e045c534b4e84a05`, launch job
`f06a3ed3a5c6f026`, and screenshot job `84669e8117ca136c` succeeded. The
screenshot shows the real app's approved HTTPS request succeeding and its
direct connection probe being denied. The 1206 × 2622 PNG has SHA-256
`96ae54c96b964d9fb7cee64dfdeb4eb940e61b5c3d0344117dea3366c1f596e4`.
The simulator XCTest in job `439aac9133c159ca` passed with zero failures.
A three-second lease expired after the test. The updated controller reached
idle with the guest disk removed 25.48 seconds after that final renewal.
The host virtualization process showed about 5.4 GiB RSS in one sample during
this build. The installed idle broker and controller together showed about
19 MiB RSS in an earlier sample.

Flutter 3.50.0 generated and analyzed a fixture with the pinned
`shared_preferences` 2.5.6 plugin inside a fresh 4 GiB guest. After the pinned
SDK's cached assets were made readable, the guest build account could read the
SDK but could not write to it. The project resolved its lockfile, compiled,
and launched on the iPhone simulator. Build job `d56ced6fbdabdc66`, launch
job `e832c3fa429c9694`, and screenshot job `e58e196f55cb8ae0` passed. The
1206 × 2622 PNG shows the app reading the value stored by the native plugin and
has SHA-256 `124b63a34561a589ae4bfe2d6b51fdf9802685446ceb4f1b61da6966974014ff`.
A three-second lease expired, and its guest disk was gone 31.81 seconds after
the final renewal.

A trusted, disconnected maintenance clone of the project-free image received
the reviewed Swift worker code and the Flutter SDK permission fix. The guest
build account could read the exact worker payload and the selected SDK paths
without write access. The refreshed powered-off base has SHA-256
`b904acc8fb519445b0d48b9a1750a0c637cffe8abaea6946ad919b394ccb10fc`.

The installed loopback API denied an invalid token, agent-only resource
approval, a second lease, a personal simulator ID and a private environment
field. It started a real VM-only lease and denied renewal after expiry. The
first check did not verify that the clone directory was removed within the
50-second observation window. Cleanup now serializes stop/delete across the
watchdog and the API and records watchdog failures. A fresh installed expiry
run is required before activation.

Regression checks verify that activation rejects evidence from a different VM
configuration and that queued public jobs stop at admission if the installed
acceptance proof is invalidated.

During provisioning, the urgent-memory guard stopped a 4 GiB guest when Tart's
regular-file stdin buffered the simulator image. Transfers now use 32 MiB
chunks, and the full 8,100 MiB runtime import succeeded with the guard active.
Xcode component installation is checkpointed, and staging cleanup tolerates a
file already removed by the runtime importer. The dedicated host account's
private keychain is initialized within the controller's launchd security session.

The Mac Build Pool menu app compiled, passed strict ad-hoc signature
verification and launched in the owner's macOS session. Regression checks
verified kernel-provided local peer identity and the aggregation of the
broker and VM-controller resource measurements. Live menu integration awaits
the final installed check. The installed owner socket returned the live
session name. Storage collection initially included retired native workspace
data and macOS-protected account caches. The measurement now uses the
isolated worker's active storage roots without changing those protections.
